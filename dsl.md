# DSL стратегий

Язык, на котором автор описывает стратегию (ФТ-12–14). Версия языка — 1.

**Статус: предложено агентом, ждёт подтверждения команды (#8).** Всё ниже — предложение, кроме того, что прямо сослано на ФТ, INV или `decisions.md`.

Связано: ФТ-12, ФТ-13, ФТ-14, ФТ-19, ФТ-22, INV-1, INV-2, INV-4, INV-6, INV-9, ADR-0008.

## Где живёт

- Разбор, линтер, проверка на чтение будущего и исполнение — одна реализация в `core` (Simulation Core). Simulation Worker отдаёт диагностики по gRPC; `backend` (модуль `workshop`) передаёт их редактору по REST и сохраняет у версии. Java DSL не разбирает, `frontend` только подсвечивает синтаксис и показывает диагностики.
- Версия стратегии хранит текст как есть и `dsl_version = 1`.
- Ограничения текста: до 64 КиБ, до 100 правил, до 50 параметров; смещение и период — до 5000 баров.

## Как исполняется

1. Стратегия описывает правила для одной бумаги. В сессии с несколькими бумагами правила выполняются для каждой бумаги отдельно, в порядке бумаг в задании; деньги общие.
2. Правила вычисляются на закрытии каждого бара t. Заявки, созданные на баре t, исполняются общей моделью не раньше open бара t+1 (INV-2, INV-3).
3. Правила проверяются в порядке текста. Все видят одно состояние — на закрытии бара t; заявки этого же бара его не меняют. Правило срабатывает не больше одного раза за бар на бумагу.
4. Индикаторы обновляются на каждом баре, даже если условие правила не вычислялось из-за `and` / `or`.
5. У правила не больше одной активной заявки на бумагу. Новая заявка правила снимает прежнюю; если новая совпадает с активной (сторона, тип, лоты, цена, срок), активная остаётся и новая не создаётся.
6. Когда позиция по бумаге становится 0, активные заявки стратегии на продажу по этой бумаге снимаются. Иначе стоп от прошлой сделки продаст следующую позицию.
7. Действие, у которого количество меньше 1 лота или количество либо цена равны `na`, заявку не создаёт.
8. В разборе расхождений (ФТ-19) стратегия вычисляется на каждом баре с состоянием человека: его позицией, деньгами, ценой входа (`decisions.md`, «Разбор расхождений»).

## Лексика

- Текст в UTF-8. Комментарий — от `#` до конца строки. Пробелы и переводы строк только разделяют лексемы.
- Идентификатор: `[a-z_][a-z0-9_]*`, регистр важен. Ключевые слова и встроенные имена занимать нельзя.
- Число: `[0-9]+(\.[0-9]+)?`. Минус — унарный оператор.
- Строка — в двойных кавычках; `\"` и `\\` — экранирование; `{выражение}` — подстановка значения; `{{` и `}}` — сами скобки.
- Ключевые слова: `param range step rule when then because buy sell cancel lots equity cash position all market limit stop take_profit day gtc and or not true false na`.

## Грамматика

EBNF (ISO 14977). `ident`, `number`, `integer`, `string` — лексемы выше.

```ebnf
strategy   = { param } , rule , { rule } ;
param      = "param" , ident , "=" , signed_num ,
             [ "range" , signed_num , ".." , signed_num , "step" , number ] ;
rule       = "rule" , string , "when" , expr , "then" , action , "because" , string ;

action     = ( "buy" | "sell" ) , size , [ order ] , [ tif ]
           | "cancel" ;
size       = expr , "lots"
           | expr , "%" , ( "equity" | "cash" | "position" )
           | "all" ;
order      = "market"
           | "limit" , expr
           | "stop" , expr
           | "take_profit" , expr ;
tif        = "day" | "gtc" ;

expr       = and_expr , { "or" , and_expr } ;
and_expr   = not_expr , { "and" , not_expr } ;
not_expr   = [ "not" ] , cmp_expr ;
cmp_expr   = add_expr , [ ( "<" | "<=" | ">" | ">=" | "==" | "!=" ) , add_expr ] ;
add_expr   = mul_expr , { ( "+" | "-" ) , mul_expr } ;
mul_expr   = unary , { ( "*" | "/" ) , unary } ;
unary      = [ "-" ] , postfix ;
postfix    = ( ident | call ) , [ "[" , [ "-" ] , ( integer | ident ) , "]" ]
           | number | "true" | "false" | "na"
           | "(" , expr , ")" ;
call       = ident , "(" , [ expr , { "," , expr } ] , ")" ;
signed_num = [ "-" ] , number ;
```

Минус в смещении `[-1]` разрешён грамматикой специально: такой текст разбирается и получает ошибку проверки E-LA01 «чтение будущего», а не синтаксическую ошибку (ФТ-14, пункт показа ТЗ).

## Типы и значения

- Типы: число и логическое. Все числа в выражениях — `double` (IEEE 754). Деньги в DSL не хранятся: цена и количество из выражения переводятся в десятичный тип при создании заявки (ADR-0008), портфель и издержки считаются только в десятичном типе (INV-6).
- `na` — нет значения. Арифметика с `na` даёт `na`; сравнение с `na` — `false`; деление на 0 — `na`.
- Используются только `+ − × ÷` и `sqrt`: они округляются по IEEE 754 однозначно, поэтому прогон побитово повторяем (INV-4). Сборка ядра — без `-ffast-math`, с `-ffp-contract=off`.
- Условие `when` должно быть логическим, количество и цена — числом; иначе ошибка E-TYPE.

## Данные

Ряды текущей бумаги на баре t (только что закрытом):

| Имя | Значение |
|---|---|
| `open`, `high`, `low`, `close` | цены бара |
| `volume` | объём бара в лотах |

`x[k]` — значение k баров назад; `x[0]` = `x`. Если истории меньше k баров — `na`. Смещение — целое число ≥ 0 или целочисленный параметр, чей диапазон не содержит отрицательных значений. Смещение допускается только у рядов и вызовов индикаторов.

Состояние портфеля на закрытии бара t (в разборе расхождений — портфель человека):

| Имя | Значение |
|---|---|
| `position` | лотов в позиции по бумаге, ≥ 0 |
| `entry_price` | средняя цена покупки текущей позиции; `na`, если позиции нет |
| `cash` | свободные деньги, ₽ |
| `equity` | стоимость портфеля по close, ₽ |
| `bars_in_position` | баров с открытия текущей позиции (0 — открыта на этом баре); `na`, если позиции нет |

Чего в языке нет намеренно: дат и времени (нет «магических дат»), новостей (INV-9), случайных чисел и часов (INV-4), обращения к другим бумагам.

## Функции

`n` — целое число ≥ 1 или целочисленный параметр с диапазоном ≥ 1. Пока значений меньше, чем нужно, функция возвращает `na`. Если на входе `na`, состояние индикатора не меняется, результат — `na`. Одинаковые вызовы (одна функция, одинаковые аргументы после разбора) — один экземпляр индикатора, в том числе внутри `because`.

| Функция | Значение |
|---|---|
| `sma(x, n)` | среднее последних n значений x |
| `ema(x, n)` | α = 2 / (n + 1); первое значение — `sma(x, n)` на n-м значении; далее α·x + (1 − α)·ema[1] |
| `rsi(x, n)` | по Уайлдеру: изменения d = x − x[1]; средние рост и падение — сначала среднее первых n значений, далее (avg[1]·(n − 1) + текущее) / n; rsi = 100 − 100 / (1 + рост/падение); если падение = 0: 100, а если и рост = 0: 50 |
| `atr(n)` | по Уайлдеру от TR = max(high − low, \|high − close[1]\|, \|low − close[1]\|); на первом баре TR = high − low; сглаживание как в `rsi` |
| `stdev(x, n)` | стандартное отклонение генеральной совокупности: sqrt(Σ(x − mean)² / n) |
| `highest(x, n)`, `lowest(x, n)` | максимум и минимум последних n значений, включая текущее |
| `change(x, n)` | x − x[n] |
| `crossover(a, b)` | a[1] <= b[1] и a > b; на первом баре — `false` |
| `crossunder(a, b)` | a[1] >= b[1] и a < b; на первом баре — `false` |
| `abs(x)`, `min(a, b)`, `max(a, b)`, `sqrt(x)` | как обычно; `sqrt` от отрицательного — `na` |

## Параметры

`param fast = 20 range 5..50 step 5`

- Значение по умолчанию обязательно. Диапазон необязателен; если есть: от ≤ значение ≤ до, шаг > 0; сетка — от, от + шаг, … ≤ до.
- Параметр в целочисленной позиции (период, смещение) должен быть целым вместе с диапазоном и шагом.
- При запуске прогона значения можно переопределить; значение вне диапазона — отказ запуска. Walk-forward перебирает сетку (ФТ-22).
- Имена параметров уникальны и не совпадают со встроенными.

## Действия

| Запись | Количество лотов |
|---|---|
| `buy N lots`, `sell N lots` | floor(N) |
| `buy X % equity`, `buy X % cash` | floor(база × X / 100 / (close × размер лота)) |
| `buy X % position`, `sell X % position` | floor(position × X / 100) |
| `sell all` | вся позиция; `buy all` — ошибка E-TYPE |

- Тип заявки: `market` (по умолчанию), `limit P`, `stop P`, `take_profit P`. Цена P переводится в десятичный тип и округляется до шага цены по правилам `decisions.md` («Деньги и округление»). P ≤ 0 — заявка не создаётся.
- Срок: `gtc` (по умолчанию) или `day`.
- `cancel` снимает все активные заявки стратегии по бумаге.
- Проверка денег и позиции при исполнении — общая для человека и алгоритма (`decisions.md`, «Заявки»).

## Причина (`because`)

- Обязательна, непустая (ФТ-12); пустая строка — ошибка E-BEC.
- Подстановки `{…}` вычисляются в момент срабатывания правила. Числа — до 2 знаков после запятой, округление половины от нуля, лишние нули отбрасываются, разделитель — запятая; `na` — «н/д»; логическое — «да» / «нет».
- Текст с подставленными значениями сохраняется у заявки и попадает в отчёт и разбор расхождений.

## Диагностики

Каждая диагностика: код, уровень (`error` / `warning`), строка и столбец начала и конца (с 1), сообщение по-русски, необязательное исправление — список замен «диапазон → текст».

| Код | Уровень | Что |
|---|---|---|
| E-SYN | ошибка | синтаксис |
| E-TYPE | ошибка | тип выражения, неизвестное имя, смещение не у ряда, нецелый период |
| E-BEC | ошибка | нет причины или она пустая |
| E-LA01 | ошибка, чтение будущего | отрицательное смещение `x[-k]` |
| E-LA02 | ошибка, чтение будущего | смещение через параметр, диапазон которого допускает отрицательные значения |
| W-LA01 | предупреждение, чтение будущего | цена сравнивается с абсолютным уровнем: одна сторона — `open`/`high`/`low`/`close` (со смещением или без) либо `sma`/`ema`/`highest`/`lowest` от них, другая — выражение только из чисел и параметров (`close > 271.35`). Абсолютный уровень обычно подобран по известной истории |
| L001 | предупреждение линтера | магическая константа (ФТ-13) |

Ошибки E-SYN, E-TYPE, E-BEC запрещают сохранить версию и запустить прогон.

### Линтер магических констант (ФТ-13)

- L001: числовой литерал внутри `rule` (условие, количество, цена, подстановка в `because`), кроме 0, 1 и 100.
- Исправление: вставить `param <имя> = <литерал>` перед первым правилом и заменить литерал именем. Имя: литерал — n-й аргумент функции `f` → `f_n` (`sma_n`); литерал сравнивается с вызовом `f` → `f_level`; иначе `p1`, `p2`, …; занятое имя получает суффикс `_2`, `_3`, …
- Предупреждения сохраняются у версии, видны на карточке и не влияют на рейтинг (`decisions.md`, «Мастерская»).
- Согласовать с владельцем линтера, который уже есть у команды: L001 повторяет его основную проверку; если в нём есть другие правила, они добавляются как L002 и далее, коды не переиспользуются.

## Чтение будущего (ФТ-14)

Уровень проверки версии — худший из найденных: ошибка > предупреждение > OK.

**До запуска** — статическая проверка: E-LA01, E-LA02 (ошибка, запуск запрещён), W-LA01 (предупреждение, запуск разрешён, пометка в отчёте).

**Во время исполнения** — «странные действия»:

| Что | Уровень |
|---|---|
| Нарушение целостности движка: запрошено значение бара позже текущего; заявка с номером свечи позже текущей; исполнение раньше open следующего бара. Проверяется в каждом прогоне; в исправном движке не срабатывает и ловит его ошибки (INV-1, INV-2) | ошибка: прогон останавливается и помечается невалидным, причина в отчёте |
| Угаданные гэпы. Гэп на баре t+1: \|open(t+1) / close(t) − 1\| ≥ 2 %. Угадан, если заявка стратегии с бара t исполнилась на open(t+1) по направлению гэпа (покупка перед гэпом вверх, продажа перед гэпом вниз). Срабатывает, если угаданных гэпов ≥ 5 и они составляют ≥ 80 % гэпов, перед которыми стратегия создала исполненную заявку | предупреждение |
| Слишком ровный результат: доля прибыльных закрытых сделок > 90 % при ≥ 30 закрытых сделках (пары покупка → продажа по FIFO) | предупреждение |

Флаг «Sharpe > 3» относится к сравнению наивного и честного прогона (ФТ-24) и здесь не повторяется. Уровень прогона — худший из уровня версии и уровня исполнения. Прогон с предупреждением засчитывается, невалидный — нет (в том числе в рейтинг).

## Пример: эталонная стратегия платформы

Используется для сравнения по умолчанию (`decisions.md`, «Разбор расхождений»). Литералов, кроме 0, 1 и 100, нет — L001 не срабатывает.

```
# Эталон платформы: пересечение скользящих средних
param fast = 20 range 5..50 step 5
param slow = 50 range 20..200 step 10
param rsi_n = 14
param rsi_high = 70 range 60..85 step 5
param stop_pct = 5 range 2..10 step 1
param size_pct = 95

rule "вход"
  when crossover(sma(close, fast), sma(close, slow)) and position == 0
  then buy size_pct % cash
  because "SMA({fast}) пересекла SMA({slow}) снизу вверх"

rule "стоп"
  when position > 0
  then sell all stop entry_price * (1 - stop_pct / 100)
  because "защитный стоп {stop_pct}% от цены входа {entry_price}"

rule "перекупленность"
  when position > 0 and rsi(close, rsi_n) > rsi_high
  then sell all
  because "перекупленность, RSI = {rsi(close, rsi_n)}"

rule "выход"
  when position > 0 and crossunder(sma(close, fast), sma(close, slow))
  then sell all
  because "SMA({fast}) опустилась ниже SMA({slow})"
```

Пример ошибки чтения будущего: `when close[-1] > close then buy 10 lots because "завтра вырастет"` → E-LA01.
