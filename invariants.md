# Инварианты

Правила, нарушение которых ломает смысл продукта: результат перестаёт быть честным, воспроизводимым или точным. Перед изменением кода, который их касается, перечитать нужный пункт. Каждый инвариант со временем должен проверяться автоматически (тест, линтер, проверка в CI) — колонка «Проверка» показывает, чем.

| ID | Правило | Почему | Где держится | Проверка |
|---|---|---|---|---|
| INV-1 | Решение (человека или алгоритма) видит только данные, доступные на его момент. Ни одна свеча, новость или метрика из будущего не попадает в ответ API, в DSL или в UI арены. | Иначе доходность завышена — ровно то, от чего защищает продукт (НФТ-1, ФТ-14) | core: рыночный цикл; backend: ответы арены; frontend: не дорисовывает и не предзагружает будущее | тест на утечку будущего в core; контрактный тест API арены |
| INV-2 | Заявка привязана к номеру последней свечи, которую видел пользователь, и исполняется не раньше open следующего бара. | Честное исполнение, одинаковое для человека и алгоритма (НФТ-1, ФТ-8) | core: исполнение; backend: приём заявок; frontend: отправляет номер свечи | тест движка |
| INV-3 | Человек и алгоритм исполняются одной моделью: комиссия, биржевой сбор, спред, проскальзывание, лимит ликвидности. Отдельной упрощённой модели нет. | Сравнение человека и алгоритма теряет смысл (ФТ-8) | core | один код исполнения для обоих режимов |
| INV-4 | Прогон алгоритма детерминирован: те же данные, версия стратегии и параметры дают побитово тот же результат. Никаких часов, случайности без seed, порядка обхода hash-контейнеров в расчёте. | НФТ-2, рейтинг на закрытых окнах | core | повторный прогон в CI сравнивает результаты |
| INV-5 | Прогон ссылается на неизменяемые версии снапшота данных и стратегии. Опубликованную версию стратегии и загруженный снапшот не меняют — только создают новые. | НФТ-3, ФТ-4, ФТ-15 | backend: workshop, marketdata | ограничения в БД, тест |
| INV-6 | Деньги — BigDecimal (в C++ — десятичный тип с фиксированной точностью), без float/double. Метрики — с погрешностью ≤ 1e-6. | НФТ-4, сверка до копейки с ручным расчётом | core, backend; frontend только отображает и не пересчитывает деньги | сверка эталонного портфеля (~20 сделок) |
| INV-7 | В слепом режиме клиент не получает название, тикер и реальные даты бумаги до конца сессии: ни в UI, ни в ответе API, ни в логах браузера. Виден только сектор экономики. Цены масштабированы (первая свеча = 100), календарь «день 1…N». | ФТ-2; если данные дошли до браузера, их видно в DevTools | backend формирует обезличенный ответ; frontend не хранит реальные данные | контрактный тест ответа API в слепом режиме |
| INV-8 | Сессия = журнал «номер свечи + заявка». Состояние восстанавливается проигрыванием журнала, после F5 или обрыва связи результат тот же. | ФТ-11, НФТ-5 | backend: sessions; core: replay | тест восстановления |
| INV-9 | Алгоритмы не видят новостей. | Детерминизм и честность рейтинга алгоритмов (границы продукта) | core, backend | DSL не даёт доступа к новостям |
| INV-10 | Внутренние данные (gRPC, PostgreSQL, ClickHouse) недоступны снаружи; вход только через Caddy по HTTPS. | НФТ-6 | инфраструктура | конфигурация Docker Compose |
