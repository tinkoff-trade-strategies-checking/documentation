# Инварианты

Правила, нарушение которых ломает смысл продукта: результат перестаёт быть честным, воспроизводимым или точным. Перед изменением кода, который их касается, перечитать нужный пункт. Каждый инвариант со временем должен проверяться автоматически (тест, линтер, проверка в CI) — колонка «Проверка» показывает, чем.

| ID | Правило | Почему | Где держится | Проверка |
|---|---|---|---|---|
| INV-1 | Решение (человека или алгоритма) видит только данные, доступные на его момент. Ни одна свеча, новость или метрика из будущего не попадает в ответ API, в DSL или в UI арены. | Иначе доходность завышена — ровно то, от чего защищает продукт (НФТ-1, ФТ-14) | core: рыночный цикл; backend: ответы арены; frontend: не дорисовывает и не предзагружает будущее | core: `Replay.NoFutureBars` (`tests/engine`), `BarCursor.VisibleNeverIncludesNextBar` (`tests/market`), `ReplaySession.UpToStepNoFuture` (`tests/worker`); до запуска — `Checker.NegativeOffsetIsLookAhead`, переопределения параметров — `Interpreter.OverrideNegativeOffsetIsRefused`; во время прогона — `RuntimeChecks.IntegrityViolationInvalidates`. backend: `SseHubTest.stepEventBarsOnlyAtCursor`. frontend: `arena.store.spec.ts` («хранилище … запросов свечей впереди курсора нет») |
| INV-2 | Заявка привязана к номеру последней свечи, которую видел пользователь, и исполняется не раньше open следующего бара. Единственное исключение — наивный прогон ФТ-24: он только для сравнения и не является результатом. | Честное исполнение, одинаковое для человека и алгоритма (НФТ-1, ФТ-8) | core: исполнение; backend: приём заявок; frontend: отправляет номер свечи | core: `MarketOrders.NotBeforeNextBar` (`tests/exec`), `Replay.OrderExecutesNextBar` (`tests/engine`). backend: `OrderApiTest.journaledAtCursorNotSeenStep` (журнал пишет шаг курсора, а не `seenStep`). Исключение — наивный прогон ФТ-24 (`CostBreakdown`, только для сравнения) |
| INV-3 | Человек и алгоритм исполняются одной моделью: комиссия, биржевой сбор, спред, проскальзывание, лимит ликвидности. Отдельной упрощённой модели нет. | Сравнение человека и алгоритма теряет смысл (ФТ-8) | core | core: `Backtest.SameEngineAsHuman` (журнал стратегии, проигранный как журнал человека, даёт те же сделки), `CostBreakdown.LastEqualsHonestRun` (последний шаг цепочки ФТ-24 = обычный прогон) |
| INV-4 | Прогон алгоритма детерминирован: те же данные, версия стратегии и параметры дают побитово тот же результат. Никаких часов, случайности без seed, порядка обхода hash-контейнеров в расчёте. | НФТ-2, рейтинг на закрытых окнах | core | core: `Determinism.SameDigestTwice`, `Determinism.DigestCoversFillsEquityAndStatus` (`tests/run/determinism_test.cpp`), `BuildFlags.NoFusedMultiplyAdd` (`-ffp-contract=off`), тесты `*.Deterministic` (`ReplaySession`, `WalkForwardRpc`, `Divergence`, `CostBreakdown`, `Metrics`); в CI `core` (`ctest`). backend: `RepeatApiTest.sameDigestMatches`, `differentDigestFlagged` (повтор прогона сверяет дайджест, UC-18) |
| INV-5 | Прогон ссылается на неизменяемые версии снапшота данных и стратегии. Опубликованную версию стратегии и загруженный снапшот не меняют — только создают новые. | НФТ-3, ФТ-4, ФТ-15 | backend: workshop, marketdata | backend: `VersionImmutabilityTest` (триггер `workshop.versions_immutable`, V5: текст, параметры и публикация версии не меняются, версии не удаляются); снапшоты — `tools/marketdata-import/tests` (`test_snapshot.py`, `test_clickhouse.py::test_reimport_creates_new_snapshot_and_old_one_is_unchanged`), CI `marketdata-import` |
| INV-6 | Деньги — BigDecimal (в C++ — десятичный тип с фиксированной точностью), без float/double. Метрики — с погрешностью ≤ 1e-6. | НФТ-4, сверка до копейки с ручным расчётом | core, backend; frontend только отображает и не пересчитывает деньги | core: `tests/money/*` (`Decimal`, перевод в proto), `ReferencePortfolio.EveryTradeMatchesTable` (`tests/exec/reference_portfolio_test.cpp`, 19 сделок из `testdata/reference-portfolio.md`). backend: `MoneyTypesArchTest` (нет полей `double`/`float` в `ru.ttsc.lab`, кроме пакета метрик `analysis.metrics`), `DecimalsTest` (`Decimal{units, nano}` ↔ `BigDecimal` без потерь). Данные: `tools/marketdata-import/tests/test_clickhouse.py::test_no_float_columns_in_schema`; отчёт: `ReportJsonMapperTest.moneyIsDecimalStringWithoutExtraZeros` (деньги отчёта — десятичные строки без лишних нулей) |
| INV-7 | В слепом режиме клиент не получает название, тикер и реальные даты бумаги до конца сессии: ни в UI, ни в ответе API, ни в логах браузера. Виден только сектор экономики. Цены масштабированы (первая свеча = 100), календарь «день 1…N». | ФТ-2; если данные дошли до браузера, их видно в DevTools | backend формирует обезличенный ответ; frontend не хранит реальные данные | backend: `BlindContractTest` (нет тикера, названия, дат, `lotSize` и рублёвых сумм), `BlindScalerTest`, `SessionViewMapperTest` (в т. ч. `stepEventOfBlindSessionIsMasked`), `FinishApiTest.revealOnlyAfterFinish`, `RunApiTest.blindRunHidesWorkerDescription`. frontend: `arena-page.spec.ts` (`blindHeaderShowsLabelAndSectorOnly`, тикер не показывается, даже если пришёл), `orders-panel.spec.ts` (`blindPortfolioInPercentNoLotSize`); история и сравнения: `HistoryApiTest.unfinishedBlindSessionTitleHidesInstrumentsAndPeriod`, `ComparisonApiTest.unfinishedSession409` (сравнение только для завершённой сессии), `ComparisonApiTest.rejectedByWorkerFailsWithoutWorkerDescription` (в ошибке задания нет бумаг и дат) |
| INV-8 | Сессия = журнал «номер свечи + заявка». Состояние восстанавливается проигрыванием журнала, после F5 или обрыва связи результат тот же. | ФТ-11, НФТ-5 | backend: sessions; core: replay | core: `Replay.Deterministic` (проигрывание всего журнала и по шагам даёт одно состояние). backend: `JournalImmutabilityTest` (триггер `sessions.journal_immutable`, V3: журнал нельзя изменить, удалить, очистить), `SessionClockTest.restartOpensPaused` (после перезапуска сессия на паузе на том же шаге) |
| INV-9 | Алгоритмы не видят новостей. | Детерминизм и честность рейтинга алгоритмов (границы продукта) | core, backend | core: `Checker.NoNewsAccess` — в DSL нет имён для новостей (`dsl.md`, «Данные») |
| INV-10 | Внутренние данные (gRPC, PostgreSQL, ClickHouse) недоступны снаружи; вход только через Caddy по HTTPS. | НФТ-6 | инфраструктура | `backend/deploy/tests/compose-ports.test.sh`, CI job `compose-ports` (порты публикует только `caddy`); ClickHouse только на чтение: воркер шлёт `readonly=1` (`core/src/worker/clickhouse/clickhouse_client.cpp`), `marketdata` — только `SELECT` |
