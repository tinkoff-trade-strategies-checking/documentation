# Инварианты

Правила, нарушение которых ломает смысл продукта: результат перестаёт быть честным, воспроизводимым или точным. Перед изменением кода, который их касается, перечитать нужный пункт. Каждый инвариант со временем должен проверяться автоматически (тест, линтер, проверка в CI).

| ID | Правило | Почему | Где держится | Проверка |
|---|---|---|---|---|
| INV-1 | Решение (человека или алгоритма) видит только данные, доступные на его момент. Ни одна свеча, новость или метрика из будущего не попадает в ответ API, в DSL или в UI арены. | Иначе доходность завышена — ровно то, от чего защищает продукт (НФТ-1, ФТ-14) | core: рыночный цикл; backend: ответы арены; frontend: не дорисовывает и не предзагружает будущее | `Replay.NoFutureBars` (`tests/engine/session_engine_test.cpp`), `InvariantsProperty.FutureBarsDoNotAffectPastSteps` (`tests/engine/invariants_property_test.cpp`), `ReplaySession.UpToStepNoFuture`, `ReplaySessionIntraday.BenchmarkStopsAtPreviousFullDay` (`tests/worker/replay_session_test.cpp`), `InMemoryBarSource.ExcludesBarsNotYetAvailableByToMs` (`tests/market/in_memory_bar_source_test.cpp`): прогон до шага `N` / `toMs` / подмена будущих баров → шаги `> N` и недоступные бары не попадают в состояние, события и отчёт |
| INV-2 | Заявка привязана к номеру последней свечи, которую видел пользователь, и исполняется не раньше open следующего бара. | Честное исполнение, одинаковое для человека и алгоритма (НФТ-1, ФТ-8) | core: исполнение; backend: приём заявок; frontend: отправляет номер свечи | `MarketOrders.NotBeforeNextBar` (`tests/exec/market_orders_test.cpp`), `Limit.NotOnPlacementStep` (`tests/exec/conditional_orders_test.cpp`), `Replay.OrderExecutesNextBar` (`tests/engine/session_engine_test.cpp`), `InvariantsProperty.OrderExecutionTiming` (`tests/engine/invariants_property_test.cpp`): заявка на шаге `K` → на шаге `K` не исполняется, исполнение не раньше `open` шага `K+1` |
| INV-3 | Человек и алгоритм исполняются одной моделью: комиссия, биржевой сбор, спред, проскальзывание, лимит ликвидности. Отдельной упрощённой модели нет. | Сравнение человека и алгоритма теряет смысл (ФТ-8) | core | нет (`Backtest.SameEngineAsHuman` удалён в `core#13` вместе с модулем алгоритмов); нужно проверить: одинаковые заявки человека и алгоритма на одних данных → идентичные сделки, издержки и итоговый портфель |
| INV-4 | Прогон алгоритма детерминирован: те же данные, версия стратегии и параметры дают побитово тот же результат. Никаких часов, случайности без seed, порядка обхода hash-контейнеров в расчёте. | НФТ-2 | core | `Determinism.SameDigestTwice`, `Determinism.DigestCoversFillsAndEquity` (`tests/engine/determinism_test.cpp`), `InvariantsProperty.DeterministicReplay` (`tests/engine/invariants_property_test.cpp`), `ReplaySession.Deterministic` (`tests/worker/replay_session_test.cpp`), `BuildFlags.NoFusedMultiplyAdd` (`tests/build/flags_test.cpp`), `DecimalDeterminism.SameOperationsGiveIdenticalBytes` (`tests/money/decimal_test.cpp`): повторный прогон с тем же входом (и сборка с `-ffp-contract=off`) → побитово одинаковый дайджест/ответ |
| INV-5 | Прогон ссылается на неизменяемые версии снапшота данных и стратегии. Опубликованную версию стратегии и загруженный снапшот не меняют — только создают новые. | НФТ-3, ФТ-4, ФТ-15 | backend: workshop, marketdata | нет (backend пустой); нужно проверить: попытка изменить опубликованную версию стратегии или загруженный снапшот → отказ, прогон привязан к неизменяемым ID версий |
| INV-6 | Деньги — BigDecimal (в C++ — десятичный тип с фиксированной точностью), без float/double. Метрики — с погрешностью ≤ 1e-6. | НФТ-4, сверка до копейки с ручным расчётом | core, backend; frontend только отображает и не пересчитывает деньги | `DecimalReference.TradeCycleByRules` и `static_assert` на запрет `float/double` (`tests/money/decimal_test.cpp`), `DecimalProperty.PortfolioCashConservation` (`tests/money/decimal_property_test.cpp`), `ReferencePortfolio.EveryTradeMatchesTable` (`tests/exec/reference_portfolio_test.cpp`), `Metrics.DailySeries` (`tests/report/metrics_test.cpp`): эталонный цикл и 19 сделок → точное совпадение до копейки, метрики с допуском `1e-9` (≤ `1e-6`) |
| INV-7 | В слепом режиме клиент не получает название, тикер и реальные даты бумаги до конца сессии: ни в UI, ни в ответе API, ни в логах браузера. Виден только сектор экономики. Цены масштабированы (первая свеча = 100), календарь «день 1…N». | ФТ-2; если данные дошли до браузера, их видно в DevTools | backend формирует обезличенный ответ; frontend не хранит реальные данные | нет (backend пустой, frontend без тестов); нужно проверить: ответ API в слепом режиме → отсутствуют тикер, название и реальные даты, цены масштабированы от 100, даты вида «день 1…N» |
| INV-8 | Сессия = журнал «номер свечи + заявка». Состояние восстанавливается проигрыванием журнала, после F5 или обрыва связи результат тот же. | ФТ-11, НФТ-5 | backend: sessions; core: replay | `Replay.Deterministic`, `Replay.ResumeFromReplayedEngineEqualsFullReplay` (`tests/engine/session_engine_test.cpp`), `InvariantsProperty.ReplayResumeFromCheckpoint` (`tests/engine/invariants_property_test.cpp`): проигрыш журнала до шага `K` с продолжением до конца → состояние движка равно полному прогону |
| INV-9 | Алгоритмы не видят новостей. | Детерминизм алгоритмов (границы продукта) | core, backend | нет (модуль алгоритмов удалён в `core#13`, backend пустой); нужно проверить: контекст алгоритма (DSL/sandbox) → нет доступа к новостям и внешним данным |
| INV-10 | Внутренние данные (gRPC, PostgreSQL, ClickHouse) недоступны снаружи; вход только через Caddy по HTTPS. | НФТ-6 | инфраструктура | нет (инфраструктурная проверка); нужно проверить: конфигурация сети/портов и сканирование снаружи → доступны только HTTPS-порты Caddy, порты gRPC/PostgreSQL/ClickHouse закрыты |
