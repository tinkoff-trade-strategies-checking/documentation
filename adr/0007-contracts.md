# ADR-0007: Где живут контракты и инфраструктура

- Ответственные: владелец продукта (решение), оформил агент `architect`
- Статус: ПРИНЯТО (решение владельца продукта, 02.11.2026)
- Дата: 02.11.2026
- Связано: НФТ-6, INV-10, ADR-0002, ADR-0005, ADR-0006, issue documentation#5
- Оригинал: на Miro нет

## Проблема
Фронт, бэк и ядро пишутся параллельно. Без общего контракта каждый придумает свой формат. Нужно решить, где лежат `.proto` (Java ↔ C++), OpenAPI (Angular ↔ Java, включая события SSE), Docker Compose и конфиг Caddy, и как генерируются клиенты.

## Альтернативы
- Отдельный репозиторий `contracts` — отклонено: пятый репозиторий и ещё один шаг в каждом изменении контракта.
- Всё в `backend` — отклонено: источником `.proto` должна быть сторона, которая реализует сервер (C++).
- **`.proto` в `core`, OpenAPI и инфраструктура в `backend`, копии у потребителей** — выбрано.

## Итоговое решение

**gRPC (Java ↔ C++)**
- Источник правды — `core/proto/`. C++-код генерируется при сборке `core` (CMake).
- `backend` хранит копию в `backend/src/main/proto/`, руками её не правит. Копию обновляет скрипт синхронизации; CI `backend` сравнивает копию с `core/proto/` ветки `main` и падает при расхождении. Java-стабы генерируются при сборке Gradle.
- Версия контракта — в имени пакета (`….v1`). Несовместимое изменение — новый пакет `v2`, старый живёт, пока `backend` не перейдёт.
- Порядок изменения: PR в `core` с новым `.proto` → PR в `backend` с синхронизированной копией.

**REST и SSE (Angular ↔ Java)**
- Источник правды — `backend/api/openapi.yaml`, contract-first: эндпоинт сначала появляется в файле, потом в коде.
- События SSE описаны там же: поток — операция с ответом `text/event-stream`, полезная нагрузка каждого события — схема в `components/schemas`; имя события SSE совпадает со значением поля-дискриминатора `type`.
- `frontend` хранит копию файла, обновляет её скриптом синхронизации, CI сравнивает с `backend` (`main`). TS-клиент генерируется из копии при сборке и не коммитится.
- Порядок изменения: PR в `backend` → PR во `frontend`.

**Инфраструктура**
- `backend/deploy/`: `docker-compose.yml` стартового окружения и `Caddyfile`.
- Образ фронтенда — `caddy` с собранной SPA в `/srv`; он же — внешний веб-сервер (ADR-0005), `Caddyfile` из `backend/deploy/` подключается в него. Наружу открыт только Caddy (INV-10).

## Допущения
- Контракт меняется реже кода, и два PR на изменение — приемлемая цена.
- CI `backend` и `frontend` может читать `main` соседнего репозитория (организация одна, репозитории открыты для команды).
