# documentation

Общие знания проекта «Т-Инвестиции: тренажёр и лаборатория стратегий» для команды и ИИ-агентов. Код живёт в `frontend`, `backend`, `core`; здесь — то, что нужно всем трём.

## Карта

| Файл | Что | Когда читать |
|---|---|---|
| `invariants.md` | INV-1…10: правила, нарушение которых ломает продукт | перед любой правкой исполнения, данных, слепого режима, денег |
| `requirements.md` | ФТ-1…21, НФТ-1…6, границы продукта | при работе над фичей — найти её ФТ |
| `decisions.md` | продуктовые детали сверх требований | когда требование допускает разные толкования |
| `architecture.md` | компоненты, Java-модули, хранилища, связи | при изменении на стыке компонентов |
| `adr/` | архитектурные решения с причинами (копии ADR-канвасов с Miro) | перед тем как менять устоявшийся подход |
| `status.md` | сроки, текущее состояние, открытые вопросы | в начале работы над новым блоком |
| `workflow.md` | как ведём задачи: доска, issue, ветки, PR, «готово» | перед началом любой задачи |

Wiki репозитория (Vision, Глоссарий на 350 строк): https://github.com/tinkoff-trade-strategies-checking/documentation/wiki. Локально — `git clone https://github.com/tinkoff-trade-strategies-checking/documentation.wiki.git`. Vision описывает раннюю версию продукта (до 21.10.2026), Глоссарий — термины рынка, данных, исполнения и метрик.

## Как читать
Не читай всё подряд — бери только то, что нужно для задачи:
- ФТ, НФТ, INV — поиском по ID (`ФТ-7`, `INV-4`), а не чтением файла целиком;
- ADR — по номеру из задачи или по оглавлению `adr/README.md`;
- Глоссарий в wiki большой — ищи нужный термин, не загружай страницу целиком.

Задачи и их ход — на доске https://github.com/orgs/tinkoff-trade-strategies-checking/projects/2 и в issue, а не в этих файлах.

## Правила правки

- Если документация репозитория противоречит существующему коду, следуй соглашениям, принятым в самом коде, а в финальном ответе укажи каждое найденное несоответствие между документацией и кодом и предложи исправления. Исключение — инварианты из `documentation/invariants.md`: их нарушение в коде считается багом, его не повторяют, а сообщают о нём.
- Приоритет источников: `requirements.md` > `invariants.md` > `decisions.md` > wiki. Нашёл противоречие — исправь младший документ или спроси команду, не выбирай молча.
- ID (ФТ-N, НФТ-N, INV-N, ADR-NNNN) стабильны: на них ссылаются код и задачи. Номера не переиспользуются; отменённое помечается, а не удаляется.
- Принятый ADR не переписывается — новое решение оформляется новым ADR.
- Решённый вопрос из `status.md` переносится в `decisions.md` или ADR.
- Пишем по-русски, коротко, без воды. Команда скептически относится к сгенерированному тексту: каждое утверждение должно опираться на решение команды, а не на догадку.
